## 1. 为什么做这次验证

A2–A5 实验（原始划分）显示 A3b 分层学习率把 Macro-F1 从 0.8022 提升到
0.8807（+0.0785）。但在把它设为默认模型之前，有两个必须先回答的问题：

1. **数据泄漏风险**：U1 诊断发现 45 对 pHash 近重复，其中 25 对跨
   train/val/test。如果这些是同一照片的变体，官方 test 集就含有"训练时
   见过"的图片，基线与所有实验的 test 指标都不可信；
2. **提升是否稳健**：A3b 的 +0.0785 来自**单个种子单次运行**，而实测发现
   同种子下重复运行的轨迹并不相同（cuDNN 非确定性），必须用配对多种子
   实验确认。

---

## 2. 阶段一结论：跨划分近重复的审查结果

对 25 对跨划分近重复**逐张目视核验**了并排联系表
（`reports/leakage_review/contact_sheet_*.png`）：

| 项目 | 结果 |
|---|---|
| 跨划分近重复对 | **25** |
| 目视确认为"同一照片变体"（同一个体、同一场景，仅重编码/重裁切） | **25 / 25** |
| 判定为 pHash 误报（不同个体） | **0** |
| MD5 完全相同的文件对 | 0（说明是重编码/重裁切变体，非字节级重复） |
| 其中 train/val → test | 24 对 |
| 其中 train ↔ val（影响验证集选模） | 1 对 |

证据强度：23 对 pHash 距离为 0 且灰度相关度 ≥ 0.9997（近像素级相同），
2 对距离为 4 但目视仍为同一拍摄场景。判定记录固化在
`reports/leakage_review/visual_verification.json`（可被用户复核覆盖）。

> **注意区分两件事**：这 25 对是**图像层面**的近重复（直接目视证据）；
> 而 U1 报告的 `corr(跨子集近重复数, F1) = 0.4807` 是**统计相关性**，
> 本身不构成"泄漏抬高了指标"的证明。本节只确认了前者。

### 去重划分（`data/processed_clean/`）

| 划分 | 原始 `data/processed` | 清洁 `data/processed_clean` | 差值 |
|---|---|---|---|
| train | 3311 | **3288** | −23 |
| val | 369 | **368** | −1 |
| test | 3669 | **3669** | **0（原样全量保留）** |

- 从官方 trainval 中排除 **24** 张与官方 test 近重复的样本（记录原因与
  匹配到的 test 图片）；
- 剩余 3656 张按 pHash 阈值构建近重复簇，整簇按"原划分多数决、平局归
  train"分配，确保簇不跨 train/val；
- **校验全部通过**：类别集合与顺序一致、MD5 跨划分重复 0、
  **pHash 跨划分近重复 0**（train/val ↔ test 与 train ↔ val 均为 0）、
  跨集合簇 0。

## 3. 实验协议

| 项目 | 设置 |
|---|---|
| 数据 | `data/processed_clean`（train 3288 / val 368 / test 3669，37 类） |
| 配置 A `baseline` | 原始 ResNet18 基线：全网络 lr=1e-3 |
| 配置 B `a3b` | 分层学习率：`--lr-head 1e-3 --lr-backbone 1e-4` |
| 两配置共享 | `--arch resnet18 --augment baseline --freeze-strategy none --batch-size 32 --epochs 10 --patience 3` |
| 种子 | `42, 2024, 7, 123, 20261017`（5 个，两配置相同） |
| 选模 | **每 epoch 按 val_acc**，与 test 无关 |
| test 评估 | 每个预计划运行**仅一次**，`ml.evaluate --data-dir data/processed_clean`；汇总在全部运行结束后才生成 |

**协议差异声明**：清洁划分的 test 集与原始划分**完全相同**（3669 张、
同文件、同标签），因此测试集层面可比；但**训练数据与选模过程已变**。
原始划分的 0.8035 / 0.8022 与本节结果**不是同条件直接比较**，本节同时
保留旧基线并说明差异。

| 指标 | 均值 | 标准差 | 范围 | 全为正 |
|---|---|---|---|---|
| Accuracy | **+0.0652** | 0.0177 | [+0.0382, +0.0777] | **5/5** |

**稳健性判断**：baseline 的种子间标准差仅 **0.0014**，而 A3b 的最小配对

5 个种子上一致。

**选模一致性**：A3b 的 val_acc（0.8973）同样远高于 baseline（0.8370），
且 val_acc 排序与 test 排序一致——**没有**依据 test 集选模的迹象。

## 7. 泄漏对指标的实际影响

对比同一配置（baseline）在两套划分上的表现：

| 口径 | test Acc | test Macro-F1 | 说明 |
|---|---|---|---|
| 原始划分（阶段 3，单次） | 0.8035 | 0.8022 | 历史基线，训练数据含 24 张泄漏样本 |
| 清洁划分（5 种子均值） | 0.8077 | 0.8055 | 泄漏样本已剔除 |

**结论：剔除泄漏后，总体指标只变化了约 +0.004（在千分位量级），
基线的总体指标并没有被泄漏显著抬高。** 但**逐品种**影响明确存在，
被泄漏的品种分数下降：

| 品种 | 原始划分 F1 | 清洁划分 F1（baseline seed42） | 变化 |
|---|---|---|---|
| japanese_chin | 0.9388 | 0.8778 | **−0.0610** |
| keeshond | 0.9463 | 0.9333 | −0.0130 |
| leonberger | 0.9447 | 0.9231 | −0.0216 |

即：**泄漏抬高的是少数品种的分数，对总体 Macro-F1 的净影响很小**
（因为这些品种的 test 样本量占比小，且其他品种略有补偿）。

## 8. 重要附带发现：A3b 对早停设置敏感

A3b 有 2 个种子（42、2024）在 **epoch 1** 就达到最佳 val_acc，随后
val_acc 回落（同期 train_acc 已 0.975，头部过拟合），`patience=3` 在
第 4 轮即触发早停；另 3 个种子跑满 10 轮、最佳 epoch 在 7–8。

这直接造成 A3b 的种子间标准差（0.0182）远大于 baseline（0.0014）：

- 早停早的种子 Macro-F1 约 0.845–0.860；
- 跑满的种子 Macro-F1 约 0.882–0.886。

**含义**：A3b 的 +0.066 是稳健的**下界**估计；若调整早停策略
（如增大 patience 或对 A3b 单独设更长 warmup），成绩可能进一步改善。
这属于**待验证**，本轮不调整（调整即构成据 test 做事后选择）。

## 9. 结论与建议

### 已被数据支持的结论

1. **官方 Oxford-IIIT Pet 的 train/test 划分确实存在跨集合图像级泄漏**：
   25 对跨划分近重复全部目视确认为同一照片变体（24 对 train/val → test，
   1 对 train ↔ val）。这是**数据集固有问题**，不是本项目划分造成的。
2. **但泄漏对总体指标影响很小**：剔除后 baseline 的 Macro-F1 仅从
   0.8022 变为 0.8055（+0.0033）。主要影响是少数品种分数被抬高
   （japanese_chin −0.061）。
3. **A3b 的提升在配对多种子验证下稳健**：5/5 种子 Macro-F1 全部提升，
   均值 **+0.0660 ± 0.0171**，最小差值 +0.0403 是基线种子噪声的约 29 倍；
   val_acc 与 test 排序一致，无测试集过拟合迹象。
4. **A3b 没有推理代价**：延迟 2.191 ms vs baseline 2.286 ms（相同量级），
   训练还更快（154s vs 207s，因早停更早触发）。
5. **逐类看 36/37 提升**，增益集中在细粒度难分品种。

### 建议（**待用户确认，本轮不执行**）

| 优先级 | 建议 | 说明 |
|---|---|---|
| P0 | 将 A3b 设为默认模型 | 证据充分：配对 5/5 全正、幅度远超噪声、无延迟代价。**但按计划须经用户确认** |
| P0 | 替换前先确定早停策略 | A3b 对 patience 敏感；建议对比 patience 3 / 5 / 10 后再选定最终配置，避免"碰运气" |
| P1 | 在报告中长期保留"原始口径 / 清洁口径"两个基线 | 便于与历史结论对照 |
| P1 | 后续 A1 补充数据必须以清洁划分为准 | 新增图片需按同样 pHash 阈值复查与 test 的近重复 |
| P2 | 向数据提供方反馈该泄漏问题 | Oxford-IIIT Pet 的官方划分含同照片变体，属数据集已知特性 |

### 明确未做的

- **未替换** `artifacts/best_model.pth`；默认模型仍是阶段 2 基线；
- **未修改** `data/processed/`、官方原始档案、任何模型权重；
- **未据 test 调整**任何 epoch/种子/参数；汇总在全部运行结束后才生成；
- A5 的 147 个难例仍**保留为人工审查任务**，未修改任何标签；
- A3b 的早停策略调优**未做**（属据结果做事后选择，需先定协议再验）。

## 11. 过程中发现并修复的代码缺陷

| 缺陷 | 影响 | 修复 |
|---|---|---|
| `find_near_duplicate_pairs` 按字符串排序返回配对，丢失 left/right 归属 | 当 test 图片名字母序小于 train 图片名时，排除步骤把两侧弄反，导致漏排（25 对只排除 23 对，清洁划分校验不通过） | 改为保留 (left, right) 归属并用 frozenset 去重；新增回归测试 |
| `_blocks` 对 (8,8) 二维数组按扁平索引切片越界，产生空块 | 分块索引退化为全量扫描（低效且脆弱） | 改为先 `ravel()` 再切片；新增回归测试 |
| `run_seed_validation.py` 的 `summary["configs"]` 被 `list(configs)` 覆盖 | 汇总统计字典被替换成列表，无法读取 mean/std | 键名改为 `config_names` |
| `per_class_f1` 混入 CSV 的 accuracy/macro avg/weighted avg 汇总行 | 逐类统计变成 40 项而非 37 项 | 按 `class_names.json` 过滤；已用各实验既有报告重新提取（未重训） |
| `build_clean_split.py` 用 `shutil.rmtree` 整目录删除 | 一次删除 7326 个文件被环境安全策略拦截，导致重建失败 | 改为增量同步（覆盖应有文件 + 只删多余文件 + 清理空目录） |
