10. 如果需求存在实质性歧义，先说明假设并询问；若可安全采用默认值，则记录默认值并继续，不要反复询问非关键细节。

## 2. 项目目标与范围

### 2.1 核心目标

实现一个 Web 系统，用户上传猫或狗的图片后，系统返回最可能的具体品种、Top-K 候选类别、模型分数和推理耗时，并可查询识别历史。

### 2.2 方案 B：多品种分类

- 使用**一个多类别图像分类模型**，直接预测具体品种。
- 优先评估 Oxford-IIIT Pet Dataset（通常包含 37 个猫狗品种）。实际类别数、标签名和可用样本以下载数据集的标注为准。
- 使用 PyTorch 与预训练 ResNet18 作为首个基线模型。
- 可以在基线跑通后增加 MobileNetV3 等对比模型，但不应因此阻塞核心系统。
- 模型输出类别索引；通过训练时保存的类别映射转换为品种名称。
- Softmax 分数是模型在当前类别集合上的归一化分数，不应对用户宣称为真实正确概率。
- 普通分类器不保证能识别训练类别之外的动物、物体或无效图片。系统必须在界面和文档中说明此限制。

### 2.3 最小可交付版本（MVP）

必须完成：

1. 数据集读取、预处理与训练/验证/测试流程。
2. 可配置的模型训练脚本。
3. 保存最佳模型权重、类别映射和实验配置。
4. 独立图片预测脚本。
5. 后端预测 API。
6. 前端图片上传、预览和结果展示。
7. 基本错误处理与上传限制。
8. 测试集指标与混淆矩阵。
9. README 中的环境安装、训练、启动、测试说明。

建议完成：

- SQLite 识别历史记录。
- Top-3/Top-5 结果展示。
- 识别统计图表。
- 模型对比实验、训练曲线、日志导出。
- 基本的历史查询和删除。

除非用户明确要求，否则不把登录/权限、云部署、复杂管理员后台列为第一阶段必要条件。

## 5. 数据集与标签约定

### 5.1 数据集选择

首选 Oxford-IIIT Pet Dataset。先核查官方页面、许可和下载说明，并记录数据集引用。若下载受限，可以使用用户提供或其他许可合适的数据集，但必须更新文档，不能假称使用了 Oxford 数据集。

### 5.2 数据准备

原始数据应与整理后的数据分开。若将原始标注转换为 `ImageFolder` 目录，提供可重复运行的数据准备脚本，并记录每个类别的样本数。

建议结构：

```text
data/processed/
├── train/
│   ├── Abyssinian/
│   ├── Bengal/
│   └── ...
├── val/
│   ├── Abyssinian/
│   ├── Bengal/
│   └── ...
└── test/
    ├── Abyssinian/
    ├── Bengal/
    └── ...
```

### 5.3 数据切分与泄漏检查

- 建议比例为 80%/10%/10%，但若沿用官方划分，应如实记录实际方案。
- 采用可复现的随机种子。
- 尽可能分层划分，使每个类别在各子集中有样本。
- 检查训练、验证、测试之间是否有相同文件或重复图像。
- 测试集只用于最终评估，不参与调参或模型选择。
- 不要把验证集或测试集的增强版本混入训练集。
- 检查损坏图片、缺失标签、类别不平衡和异常样本。
- `train`、`val`、`test` 的类别到索引映射必须完全相同；若使用 `ImageFolder`，验证并断言 `class_to_idx` 一致。

### 5.4 图像预处理

ResNet18 预训练权重对应的预处理规范应与 torchvision 版本相匹配。若训练使用：

- RGB 三通道；
- 224×224 尺寸；
- ImageNet mean `[0.485, 0.456, 0.406]`；
- ImageNet std `[0.229, 0.224, 0.225]`；

则验证、测试和线上推理必须使用兼容的评估变换。训练时可采用适度的随机水平翻转、轻微旋转等增强；验证和测试不使用随机增强。

优先考虑使用所选权重的官方 transforms，或在配置中明确并测试自定义 transforms，避免训练和部署预处理不一致。

## 6. 模型实现要求

### 6.1 首个基线

- 使用 torchvision 的 ResNet18 预训练权重。
- 将最后的全连接层替换为 `num_classes` 个输出。
- 使用 `CrossEntropyLoss`，训练输入是 logits，标签是整数类别索引。
- 首先训练全模型或先冻结主干、训练分类头；根据实际显存和实验结果选择，并在配置中记录。
- 采用 AdamW 或其他合理优化器。
- 使用验证集选择最佳权重。
- 根据验证指标选择模型，不可根据测试集反复挑选模型。

### 6.2 训练输出

至少生成：

- `artifacts/best_model.pth`
- `artifacts/class_names.json`（类别索引顺序与训练集一致）
- `artifacts/experiment_config.json`
- `reports/train_log.csv` 或等价训练日志
- `reports/accuracy_curve.png`
- `reports/loss_curve.png`

建议实现：

- 固定随机种子；
- 可配置 batch size、epoch、学习率、数据目录、输出目录和设备；
- 学习率调度；
- 早停（可选）；
- 保存最近检查点和最佳检查点；
- 中断后恢复训练（时间允许时）；
- 每轮输出 train/val loss、accuracy、学习率；
- 捕获并清楚报告数据路径、设备或权重错误。

不得把示例指标或占位数写成真实实验结果。

### 6.3 独立评估

`evaluate.py` 应加载最佳权重，在独立测试集上计算并保存：

- Accuracy；
- Precision、Recall、F1；
- 多分类的 Macro-F1；
- 每类别分类报告；
- 混淆矩阵；
- 推理时间（说明硬件、batch size、是否包含预处理）。

推理耗时应合理预热并重复测量；区分单张延迟与批处理吞吐量。报告中写明硬件与软件版本。

### 6.4 推理接口

- 模型在服务启动时加载一次并复用，不能每次请求都重新加载权重。
- 调用 `model.eval()`，推理使用 `torch.inference_mode()` 或 `torch.no_grad()`。
- 使用与训练相同的类别映射。
- 返回 Top-K 品种名称与分数，K 不得超过类别总数。
- 模型权重路径应由配置或项目路径推导，不能依赖启动命令所在目录。
- 模型未训练、权重文件缺失、标签文件不匹配时，应给出明确错误，不得静默返回假结果。

## 7. 后端 API 规范

推荐 API：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/predict` | 上传图片并识别 |
| GET | `/api/history` | 分页查询识别历史 |
| GET | `/api/history/{record_id}` | 查询记录详情 |
| DELETE | `/api/history/{record_id}` | 删除一条记录 |
| GET | `/api/stats` | 统计数据 |

### 7.1 预测请求

`POST /api/predict` 使用 `multipart/form-data`，字段名为 `file`。

建议响应：

```json
{
  "success": true,
  "record_id": 1,
  "predictions": [
    {"breed": "实际类别名", "confidence": 0.82}
  ],
  "elapsed_ms": 35.4
}
```

以上数值与类别仅为接口格式示例，不能作为真实推理结果。若未启用数据库，可省略 `record_id`，但需在文档中说明。

### 7.2 输入校验与安全

- 设置可配置的文件大小上限，例如 10 MB。
- 使用 Pillow 等库实际解析图片，不只信任文件扩展名或 MIME 类型。
- 只接受支持的图片格式；解码失败返回 HTTP 400。
- 约束图片像素总数，降低超大图片导致的内存消耗风险。
- 将上传文件保存为随机生成的服务端文件名，禁止直接使用用户提供的路径或文件名。
- 限制上传目录访问；清理过期图片。
- 处理空文件、损坏图片、模型未加载、推理异常、数据库错误。
- 避免把内部堆栈、绝对路径或敏感配置返回给客户端。
- 配置开发环境 CORS；不要在生产环境无理由允许任意来源。
- 如果保留图片，应在 README 中说明保留方式和删除策略。

### 7.3 性能和并发

- 模型初始化应在应用 lifespan 或等价启动逻辑中完成。
- GPU 推理应避免不受控的并发访问；按需要使用线程池或推理锁，并进行测试。
- 不要在异步路由中直接执行耗时同步任务而不考虑事件循环阻塞。
- 不得声称具有真实生产级并发能力，除非经过测量和验证。

- 数据库文件路径由配置管理。

- 历史查询需要分页和排序。
- 统计接口的数据应来自真实数据库记录，不可用硬编码统计数。
- 数据库迁移方案应与项目复杂度相匹配；简单 MVP 可以在 README 中说明初始化方法。

## 10. 测试与验收标准

### 10.1 数据和模型测试

- 数据目录缺失时，错误信息明确。
- 类别映射一致性断言有效。
- 模型输出维度等于类别数。
- 单张合法图片可完成推理。
- Top-K 输出数量不超过类别总数，分数为有限数值。
- 权重缺失或标签数量不一致时，启动或预测应失败并说明原因。
- 测试集指标由真实推理生成。

### 10.2 API 测试

至少覆盖：

- 健康检查成功；
- 合法图片上传；
- 空文件；
- 不支持的文件类型；
- 伪装成图片但无法解码的文件；
- 超过文件大小限制；
- 超高分辨率图片；
- 模型文件缺失；
- 数据库写入或查询异常（若实现数据库）；
- 历史查询分页与删除（若实现历史）。

测试不得要求预先下载真实大数据集才能运行。优先为单元测试创建临时的小型合成图片和轻量假模型；合成数据只用于测试软件流程，不能作为模型实验结果。

### 10.3 前端测试

- 无文件时不能提交；
- 上传中有加载状态；
- 正确展示 API 返回的类别与分数；
- 服务不可用时有错误提示；
- 清除图片后状态正确；
- 历史页的分页、筛选和删除功能正常（若实现）。

### 10.4 最终验收

只有在实际运行后才可以标记通过。最终应确认：

- 从 README 的命令可安装依赖并启动；
- 训练流程可运行，或 README 清楚区分训练前和训练后的准备步骤；
- 单图推理可独立运行；
- 后端能返回真实模型推理结果；
- 前端能够上传图片并展示结果；
- 测试命令执行结果已记录；
- 模型实验图表与指标均来自真实运行；
- Git 中没有虚拟环境、缓存、私密文件或不必要的大型数据集。

## 14. 开发命令参考

具体命令应按操作系统、虚拟环境、包管理器和目录结构调整。

### 安装 Python 依赖

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS/Linux：

```bash
source .venv/bin/activate
```

然后安装项目依赖：

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

PyTorch 安装命令应根据官方安装页面和实际 CPU/CUDA 环境确定。

### 模型训练与评估（目标命令）

```bash
python -m ml.train
python -m ml.evaluate
python -m ml.predict --image path/to/image.jpg
```

Agent 应让 CLI 参数和 README 保持一致；如果最终实现采用其他命令，更新本文件或 README，不要留下不可执行的命令。

### 后端启动（目标命令）

```bash
uvicorn backend.app.main:app --reload --port 8000
```

最终导入路径应以真实项目结构为准。

### 前端启动（目标命令）

```bash
cd frontend
npm install
npm run dev
```
