## 0. 目标与执行路线

### 总目标

在尽量不损害其他类别的前提下，提高 `collie`（柯利牧羊犬）和 `border_collie`（边境牧羊犬）的区分能力，特别是减少真实 `collie → border_collie` 的误判；同时确认改善不是通过牺牲其余类别获得的。

### 固定顺序

| 阶段 | 任务 | 重要性 | 结束条件 |
|---|---|---|---|
| S0 | **轻量安全固化 U5.5** | 必要但从简 | 已保存当前工作区状态；完成小范围变更审核与提交，或记录无法安全拆分的项目并保留现场；V2.1 正常运行 |
| U6-A | **建立 V2.1 验证集基线** | 最高 | 生成可复现的 136 类、原 37 类、新增 99 类和目标两类指标；提前冻结成功标准 |
| U6-B | **数据与错误模式诊断** | 最高 | 明确毛色、误判去向、样本不平衡等证据及其局限，不改标签 |
| U6-C | **小规模、逐项针对性实验** | 最高 | 只运行有诊断依据的实验；每次仅改变一个主因素，产物独立保存 |
| U6-D | **比较全部 136 类并确定候选** | 最高 | 根据预先冻结的验证集标准选择或否决候选，不用测试集选参 |
| U6-E | **最终测试集评估与报告** | 条件执行 | 只有选定最终候选后才进行一次测试集评估；测试结果不再用于修改该候选 |

**尽快推进原则**：先做 S0 的轻量固化，不做全仓库清理；随即进入 U6-A/U6-B。不要让提交整理或额外的文档美化阻塞边牧诊断与实验。

## 5. U6-C：有针对性的实验（本计划重点）

### 5.1 实验原则

1. V2.1 冻结 checkpoint 只读；每个实验从同一份 V2.1 checkpoint 初始化，确认 136 类数目、标签顺序和参数加载一致。
2. 不生成或保存合成图片到数据集目录。增强只在训练 DataLoader 中即时应用。
3. 一次只改变一个主因素；学习率、batch size、epoch、early stopping、scheduler 等基线参数保持一致，除非该实验变量本身就是学习率或输入分辨率。
4. 所有实验产物进入独立目录，绝不写入 `artifacts/v2_1_136classes_seed42/`、`artifacts/best_model.pth` 或其配置目录。
5. 先做少量高价值实验；不要求机械地跑完所有候选。如果前两项均无改善，先回看诊断，不要继续堆叠增强和调参。
6. **禁止通过修改类别标签、测试集图片或测试指标来“改善”结果。**

### 5.2 推荐执行次序

| 顺序 | 实验 ID | 单一主要变量 | 设计要点 | 风险与检查 |
|---|---|---|---|---|
| 1 | `exp01_pair_color_jitter` | 只对 `collie` / `border_collie` 训练样本施加温和颜色扰动 | 亮度、饱和度与色调范围保守；先在现有验证集诊断确认颜色偏差假设值得测试 | 不能把貂色/陨石色等视觉特点完全破坏；记录增强参数与随机种子 |
| 2 | `exp02_pair_sampler` | 对目标两类采用温和的加权采样或类别权重（二选一） | 保持图像增强和训练超参与基线一致 | 监控目标类过拟合、相近犬种及其余 134 类退化 |
| 3（条件执行） | `exp03_color_plus_sampler` | 仅当 exp01、exp02 单项结果可解释且至少一项呈现改善趋势时，测试组合方案 | 在前两项之一的基础上只追加另一个已验证有效因素 | 若单项无效，不直接组合多个无效因素 |
| 4（条件执行） | `exp04_resolution` | 只有诊断显示细粒度形态/局部特征不足，才比较 256 或 288 输入分辨率 | 作为独立对照，记录显存、延迟和吞吐 | 不与颜色增强、采样变化同时启用 |
| 5（暂缓） | `exp05_pair_finetune` | 只在前面有明确改善方向但仍未达标准时，才评估定向微调 | 必须先定义参数冻结范围、损失函数影响及恢复方案 | 对 136 类校准风险高；不作为第一轮默认实验 |

### 5.3 独立目录与配置

示例路径：

```text
artifacts/v2_2_border_collie_exp01_pair_color_jitter_seed42/
artifacts/v2_2_border_collie_exp02_pair_sampler_seed42/
artifacts/v2_2_border_collie_exp03_color_plus_sampler_seed42/  # 条件执行
reports/u6_border_collie/
```

每个实验至少保存：`best_model.pth`、`experiment_config.json`、类别映射副本或 SHA256、训练日志、最佳 epoch、val 指标和耗时。目录非空时拒绝覆盖；使用新目录或新实验 ID。

### 5.4 随机种子与筛选效率

- 首轮用固定 seed 42 做**小规模筛选**，优先比较 exp01 和 exp02，避免盲目全跑。
- 若实验在验证集上达到预先冻结的基本标准，入围方案需再用至少两个随机种子复核方向是否一致；不能只挑最好的 seed。
- 对同一候选进行多 seed 复核时，分别保存每个 seed 的权重与结果，再报告均值、标准差和各 seed 结果。验证集虽可用于选择，但样本量小，因此不能把单次提升等同于稳定泛化。
- 不做与诊断无关的大规模超参搜索。

## 6. U6-D：比较全部 136 类并决定最终候选

所有候选均使用与 V2.1 **相同的 validation split、评估代码和预处理**，产出一张基线对比表和每类差异表。

### 6.1 必须报告的指标

1. 全部 **136 类**：Accuracy、Macro-F1、Weighted-F1。
2. 原有 **37 类**：Accuracy、Macro-F1、Weighted-F1。
3. 新增 **99 类**：Accuracy、Macro-F1、Weighted-F1。
4. `collie` 和 `border_collie`：各自 Precision / Recall / F1、support、双向混淆数和混淆率。
5. 误判去向：目标两类流入/流出的 Top 类别，以及 Shetland Sheepdog 等相近类的变化。
6. 每类 F1 的相对 V2.1 变化、退化最明显的类别及其 support。
7. 模型校准、推理时延、显存或吞吐如有实测则附上；不得把未测值当作实测结果。
8. 小样本不确定性：对目标类报告计数分母和适当的 Wilson / bootstrap 区间；说明区间不能消除验证样本偏少问题。

### 6.2 成功标准（训练前冻结）

U6-A 重算验证集基线后，须生成 `u6_success_criteria.json`，明确最后要比较的阈值。建议初值如下；可以在**任何候选实验结果产生前**结合基线确认一次，之后冻结：

| 指标 | 建议门槛 |
|---|---|
| `collie` F1（val） | 相对 V2.1 提升至少 **+0.10 绝对值**，或在多 seed 下有一致且有实际意义的改善并由报告说明 |
| `border_collie` F1（val） | 不低于 V2.1 基线 **−0.02** |
| 两类双向混淆 | 合计错误数/率下降至少 **30%**，同时报告绝对计数，避免小分母放大百分比 |
| 136 类整体 Macro-F1（val） | 相对 V2.1 退化不超过 **0.01** |
| 原有 37 类子集 Macro-F1（val） | 退化不超过 **0.005** |
| 新增 99 类子集 Macro-F1（val） | 退化不超过 **0.01** |
| 其余类别 | 不得存在未经解释的严重退化；必须列出每类变化，而非只报告总体平均值 |
| 稳定性 | 入围方案在至少 3 个种子中，主要改善方向须至少 2/3 一致；对不一致结果如实报告 |

如果由于样本量小，无法合理达到上述标准，不准调低标准凑通过；可以得出“现有数据不足以证实改进”的结论，保留 V2.1。

### 6.3 候选决策

- 仅验证集评估满足冻结门槛的一个候选可以进入 U6-E。
- 若没有候选通过，停止实验，给出失败分析与数据增补建议，不要自动切换模型。
- **不允许只凭 `collie` 指标上涨就选择模型**；全部 136 类、原 37 类、新增 99 类和逐类退化必须一起审查。

## 7. U6-E：最终测试集评估（条件执行，严格一次）

1. 只有 U6-D 选定一个候选并记录其 checkpoint SHA256、配置、随机种子和验证集结果后，才运行一次完整 test 评估。
