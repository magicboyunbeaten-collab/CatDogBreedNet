## 1. 安全规则

### 1.1 允许操作

- 读取文件、`git status`、`git diff`、`git diff --cached`、`git log`、`git show`、`git rev-parse`。
- 编辑本文第 2 节指定的两个测试相关位置（不得顺手重构生产代码）。
- 运行后端测试、前端测试与构建。
- 只有第 3 节全部测试通过且核对精确暂存区后，才可按 A/B/C/D 顺序执行本文列出的 `git add -- <精确路径>` 与 `git commit`。

### 1.2 禁止操作

- 禁止 `git add .`、`git add -A`、路径通配符暂存。
- 禁止 `git reset`、`git clean`、`git checkout`、`git restore`、`git stash`、`git rebase`、`git commit --amend`、强制推送或任何远端 push。
- 禁止删除/覆盖任何现有模型权重、训练实验、诊断报告、CSV、截图、缓存、临时 runtime、数据、数据库或上传文件。
- 禁止修改标签、数据划分、候选组成员、阈值、版本标识或默认模型配置。
- 禁止训练新模型、访问 `data/v2_processed/test`，禁止写入正式 `data/app.db` 或项目 `uploads/`。
- 禁止将 `reports/`、`artifacts/`、`data/`、`uploads/`、`.cache/`、隔离 `runtime_*`、整个 `scripts/` 或 `md/` 目录加入提交。
- 不得声称“所有 untracked 均已解决”而实际把临时文件删除或隐藏。剩余文件必须保留并分类记录。
