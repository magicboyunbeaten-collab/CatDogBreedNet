## 2. U6.1-A：确认 warm-start 初始化没有问题

上一轮报告指出，旧实现曾无条件跳过分类头，导致 136→136 warm-start 可能重置 `fc.weight` / `fc.bias`。训练代码据称已修复：类别名和顺序完全一致时，应连分类头一起继承，并在日志中记录 `head_transferred=True`（或等价、可核验的初始化审计信息）。

开始任何新训练前，必须逐项核验：

1. 当前 `ml/train.py::initialize_from_checkpoint` 对完全相同的 136 类映射是否继承 `fc.*`。
2. 上一轮 `exp01`、`exp02`、`exp04` 及两个额外 seed 的日志是否明确显示分类头已继承；检查类别名、类别顺序和 checkpoint 哈希。
3. 检查是否有初始化前后张量比对、加载键统计或其它可信证据证明 `fc.*` 未被重新初始化。
4. 在不读取 test split 的条件下，运行现有初始化相关单测与完整后端测试。
5. 将核验结果写入 `reports/u6_1_low_lr/warm_start_audit.md`。

**判定规则**：
- 如果现有实验日志证明分类头确实继承：如实记录，不重跑旧实验。
- 如果旧实验无法证明继承，必须把旧实验标为“初始化证据不足”，不得用于声称变量无效；新实验须重新执行并产生明确日志。
- 若当前初始化代码或单测失败，先做最小修复并补测试。不得改动推理路径、正式默认配置或已保存的 V2.1 权重。

## 3. U6.1-B：低学习率对照实验

### 3.2 统一低学习率协议

- `--init-from artifacts/v2_1_136classes_seed42/best_model.pth`

其余训练参数（包括 batch size、epoch 上限、patience、scheduler）以既有训练配置为准，先从 `experiment_config.json` 与脚本核实并记录；除明确列出的变量外，不要同时更改其它设置。如果当前 CLI 没有直接支持某个参数，先做最小兼容实现并添加单测，不能默默忽略参数。

## 4. U6.1-C：每个候选都必须进行全类别比较

每个训练完成的候选均使用与训练分辨率相匹配的评估流程，在 **validation split** 上输出下列指标：

### 4.1 目标两类

- `collie`、`border_collie` 的 Precision、Recall、F1、support。
- `collie → border_collie` 与 `border_collie → collie` 的错误数和分母。
- 与冻结 V2.1 基线相比的绝对差值。
- 如输出置信区间，明确方法、分母和小样本限制；不可将 15–16 张验证样本上的微小波动描述为确定性提升。

### 4.2 三组整体指标

必须同时报告：

1. 全部 136 类：Accuracy、Macro-F1、Weighted-F1。
2. 原有 37 类子集：至少 Macro-F1，并保持与基线同样的筛选和统计口径。
3. 新增 99 类子集：至少 Macro-F1，并保持与基线同样的筛选和统计口径。
4. 136 类逐类 F1 delta，列出退化最大的至少 10 类，以及改善最大的至少 10 类；保留每类 support。
5. 混淆矩阵/逐图预测差异，特别检查柯利、边境牧羊犬、喜乐蒂、彭布罗克威尔士柯基等容易混淆类别。
6. 推理延迟若有测量，需同硬件、同 batch/单图口径比较；不以不同测量条件下的延迟下结论。

**不得只报告目标两类提升而隐去其它类别退化。**

## 5. 冻结成功标准（不可修改）

从 `reports/u6_border_collie/u6_success_criteria.json` 读取并核对成功标准。本轮不得重写、降低或通过改变口径规避标准。当前报告中记录的关键门槛包括：

- `collie` F1 ≥ 基线 +0.10（当前基线 0.5882，对应 ≥ 0.6882）。
- `border_collie` F1 不低于基线 −0.02（当前基线 0.6667，对应 ≥ 0.6467）。
- 两类双向错误数 ≤ 4（相对基线 6 至少减少 30%）。
- 136 类 Macro-F1 不低于基线 −0.01（当前基线 0.803806）。
- 原有 37 类 Macro-F1 不低于基线 −0.005（当前基线 0.899582）。
- 新增 99 类 Macro-F1 不低于基线 −0.01（当前基线 0.782694）。
- 多 seed 方向一致性必须按冻结 JSON 的定义执行；不能只挑最好的 seed 报告。

若报告中的精度位数或指标定义与 JSON 不一致，**以冻结 JSON 和已保存的基线评估口径为准**，先记录差异并说明，不得擅自修正成功标准。

## 6. 多 seed 复核和停止条件

1. 三个首轮实验都完成后，先比较 seed 42 的验证指标与冻结标准。
2. 只有呈现合理正向信号、且没有明显整体或局部退化的候选，才追加多 seed 复核。优先对 `exp06` 进行 seed 7 与 seed 2024 的独立重复；若 `exp07` 或 `exp08` 的表现值得继续，也需说明其依据和额外成本。
3. 每个 seed 使用独立的新输出目录与随机种子，不得覆盖其它 seed 的权重、日志或报告。
4. 汇报均值、标准差、最好/最差值、方向一致性；不能把单 seed 最佳值当作稳定效果。
5. 如果无候选满足所有冻结标准，结论必须是“未达标，继续保留 V2.1”，不可自行进入最终测试评估。
6. 即使某候选似乎达标，本阶段也**不执行 U6-E、不访问 test split**。先停下来提交报告并等待人工批准，再单独安排一次最终确认性评估。

## 7. 学习率效应与结果解释

- 上一轮 exp01 / exp02 的低表现可能被 warm-start 后的学习率冲击影响。新实验应结合 epoch 1 到后续 epoch 的学习曲线判断，但不能只因初期指标下跌就临时改动学习率。
- 如果本轮三个实验均显示训练初期明显退化、长时间不能恢复，记录证据并停止将它们解释为变量无效；提出新的低学习率方案供人工决定，不得在同一个实验中无记录地变更超参。
- 只有在未来设计了额外学习率消融后，才能比较颜色扰动或采样策略的独立作用。当前结果表述为“在指定低学习率协议下的表现”，不要泛化为这些方法普遍无效。
