## 2. 模型方案

### 2.1 模型目标

- 模型版本标识建议：`v2_1_136classes_candidate`。
- 类别数：136。
- 架构：沿用当前项目 ResNet18 分类架构及既有图像预处理方式，除非仓库代码核查发现实际架构并非如此；若发现差异，以现有实际实现为准并报告。
- 初始化：优先从当前 **V1.1 checkpoint** 加载与新模型形状匹配的骨干网络参数，并重新初始化 136 类分类头。不要把 37 类输出层权重错误地当作 136 类输出层使用。
- 加载 checkpoint 时先确认其保存格式，明确提取实际 state dict；只加载键名和张量形状匹配的参数。可以排除旧的最终分类层，但必须断言未匹配项仅为预期的分类层参数（或由实际架构核实后的等价层）；不允许通过无检查的宽泛 `strict=False` 静默吞掉其他缺失参数。
- 如果无法安全地从 V1.1 checkpoint 迁移骨干参数，应停止并报告，不得擅自改成另一套未记录的初始化方法。

### 2.2 训练参数

- 随机种子：`42`，并尽可能固定 Python、NumPy、PyTorch 与 DataLoader 的随机性；在配置中记录实际可复现性限制。
- 训练超参数：优先继承仓库内 V1.1 正式训练配置，避免训练方案同时发生多项变化。
- 已知 V1.1 参数参考：分类头学习率 `1e-3`、骨干学习率 `1e-4`、early stopping patience `10`。训练前必须从配置或训练记录中核实这些值；仅当与当前实现相符时才采用，并在 `experiment_config.json` 中记录。
- 最大 epoch 数、batch size、优化器、scheduler、损失函数、数据增强、权重衰减、AMP 等，以当前项目已验证的训练配置为准。不要自行猜测或随意更换；若训练 136 类确实需要修改，先在报告中说明修改理由及其对 V1.1 可比性的影响。
- 训练只读取 `data/v2_processed/` 下的 train 和 val。不得把 test 图像混入 train/val，也不得用 test 指标做早停或选 checkpoint。
- 如果既有训练管线采用类别权重、采样器或不均衡处理，先记录并沿用；不要无依据地改成另一种策略。

### 2.3 验证与最佳模型选择

- 每个 epoch 计算并记录验证集 loss、Accuracy 和 Macro-F1；能以合理成本计算时，也记录 per-class precision/recall/F1。
- 最佳 checkpoint 和 early stopping 使用验证集 **Macro-F1** 作为主要监控指标，以避免只偏向样本较多的类别；同时报告验证集 Accuracy 和 loss。若项目现有 early-stopping 实现不支持按 Macro-F1 监控，可在不影响既有模型管线的前提下作最小改动，并添加测试。
- 保存最佳模型与最后一个 epoch 的模型，两者均写入独立实验目录。
- 日志中记录每轮耗时、学习率、train loss、val loss、val Accuracy、val Macro-F1 和 early-stopping 状态。

## 4. 正式训练与异常处理

1. 先用小批量做一次 **smoke test**：能够读入 train/val、输出 136 个 logits、loss 可正常反传、一个 batch 能完成训练步骤；确认输出仅写入候选目录。
2. smoke test 通过后再启动完整训练。
3. 运行过程中不要启动第二个重复训练进程。遇到显存不足、NaN、解码失败、标签越界、类别数非 136、输出写到正式目录或 checkpoint 加载异常时，应停止运行并保存日志，禁止通过删除数据、改正式 checkpoint 或静默跳过错误来继续。
4. 若需要修改 batch size 等以解决硬件限制，只允许做最小必要变更；记录变更前后参数并重跑 smoke test。不要改变数据划分或使用测试集辅助解决训练问题。
5. 每次保存 checkpoint 后，记录文件大小和 SHA256；确认候选 checkpoint 可被对应模型结构加载，且输出层维度为 136。不要覆盖已有实验输出。

## 5. 最终评估要求

训练和 checkpoint 选择全部结束后，使用最终最佳 checkpoint 对 **test 集进行一次正式评估**。不要在查看测试结果后返回调整模型并继续把同一 test 集当成未见数据。

报告必须同时提供：

1. 全部 136 类：Accuracy、Macro-F1、Weighted-F1、每类 Precision/Recall/F1、混淆矩阵或可审查的混淆统计。
2. 原有 37 类子集：在它们原有的测试样本上单独统计 Accuracy、Macro-F1、Weighted-F1，用于观察新增类别训练后原有识别能力是否退化。
3. 新增 99 类子集：单独统计上述指标，并列出表现最差的类别及样本数量。
4. 原有猫类 12 类、原有狗类 25 类、新增狗类 99 类的分组结果；清楚说明分组口径。
5. 边境牧羊犬、AmStaff、APBT、English Cocker、Scottish Terrier 等重点类别的样本数和独立分类结果。
6. 与 V1.1 比较时注明数据协议与类别空间不同：V1.1 是 37 类模型，V2.1 是 136 类模型，不能把两个模型在不同类别空间下的 overall 指标直接解释成严格同协议的胜负。可在原有 37 类测试子集上辅助比较，但要说明预测空间从 37 类扩展到 136 类后，错误去向发生变化。
7. 推理延迟可作为可选项，需记录硬件、预热次数、计时方式、batch size；不要把未经同条件测量的数据当作公平对比。
8. 记录最佳 epoch、停止原因、总训练时间、环境版本（Python、PyTorch、CUDA/GPU），以及训练期间是否发生过重试或配置变动。

**严禁**在 test 集上挑选最佳 epoch、调整阈值或调参。若确实要进行第二轮实验，应先记录本轮结果，再依据验证集/新的独立测试方案设计下一轮。
