# V2.1 相近犬种候选提示与边牧复核整合任务（U5）

## 0. 任务目标

基于已经完成的 V2.1（136 类）模型和诊断结果，优化相近犬种的识别结果展示，并整理用户已完成的边牧 / 柯利人工复核信息。

**本任务以推理结果展示和诊断资料整理为主，不训练新模型，不更改任何原始图片标签，不合并模型类别，不切换正式模型。**

当前正式系统继续使用 V1.1（37 类）；V2.1 仍为独立候选模型。本任务不得让 V2.1 自动接入正式系统。

## 1. 已确认的业务口径

### 1.1 AmStaff / Staffordshire Bull Terrier / American Bulldog 候选组

当 V2.1 模型的预测显示图片很可能属于以下三个类别之一，且模型在组内难以明确区分时，前端应呈现：

1. 一个明确的“模型首选”——仍为模型原始 top-1 类别；
2. 一个“外观相近的候选品种”区域，列出这三个候选，允许用户自行选择更符合图片的品种；
3. 必要的解释提示：单张图片未必足以可靠地区分这些相近品种。

候选组的三个类别（canonical labels）：

- `american_staffordshire_terrier` — 美国斯塔福郡梗（AmStaff）
- `staffordshire_bull_terrier` — 斯塔福郡斗牛梗（SBT）
- `american_bulldog` — 美国斗牛犬

**APBT (`american_pit_bull_terrier`) 仍保持独立的原始类别，不得在本任务中自动合并、改名或映射成上述三类之一。** APBT 的高混淆问题继续保留在诊断说明中，不得隐去。

### 1.2 置信度 / 分数展示规则

- 不得为了视觉效果直接篡改模型原始 Softmax 概率；不得把其他类别人工压成个位数百分比。
- 模型原始 top-1、原始类别概率/得分必须保留供调试和追踪。
- 为了让用户在候选组内比较，可以基于三个候选的原始概率计算组内相对得分：
  `group_score_i = p_i / sum(p_j for j in candidate_group) * 100`。
- 组内得分必须清楚标为“候选组内相对得分”，**不能标成整体识别置信度、真实概率或准确率**。
- 如果三个候选的总概率质量太低，不能仅因 top-1 偶然落在组内就展示强烈的候选提示；应该按验证集确定的阈值判断是否触发。
- 当 top-1 在候选组内，且组内前两名差距较小/组内存在多类竞争时，可展示候选组。阈值必须只用 validation split 选择并记录原因，不得用 test split 调参。
- 如果不满足触发条件，沿用现有正常识别结果展示，不强行套入候选组。
- 候选组以外的类别可折叠显示或不在主结果区展示；不得虚构或修改它们的分数。

### 1.3 用户选择与原始预测分离

- 用户可以在候选组中选择其认为更符合的品种。
- UI 应分别保留“模型预测”和“用户选择”，不允许用户选择覆盖模型原始 `predicted_breed`、分数、原始预测结果或历史记录。
- 本任务第一阶段只需实现当前识别结果页中的交互状态，不新增数据库字段、不迁移 SQLite、不更改既有历史记录。如需持久化人工选择，另行提交任务评审。
- 未经明确同意，不将用户选择自动当作训练标签。

## 2. 边牧 / 柯利人工复核资料整理

用户已完成边牧相关图片人工复核，判断依据为人工主观观察。此前诊断摘要包括：

- 全 split `collie → border_collie` 共 17 张误判；原报告称其中 5 张自动识别为黑白、2 张陨石、1 张三色、9 张颜色待复核。
- 先前人工抽查的 8 张错误图片均为黑白配色；这一现象不能单独证明所有黑白柯利都会被判为边牧。
- 自动毛色启发式对 297 张图片仅覆盖 130 张，另 167 张为 uncertain，不能把该启发式结果当成可靠真值。

Agent 必须先查看项目当前版本中的 `reports/v2_1_coat_pitbull_diagnostics/coat_color_review_queue.csv` 及其人工审核字段/附加记录：

1. 如果用户已在本地填入明确的人工复核结果，则读取并汇总这些结果，输出按类别、人工确认毛色和预测正确性分组的统计表。
2. 如果文件仍未保存人工审核标记，不要推断人工结论、不重写原 CSV；报告明确指出目前能读取到哪些人工结果、缺少哪些结构化记录，并保留现有文件。
3. 不根据毛色或主观外观自动更改 `collie` / `border_collie` 标签；不移动、删除、重命名或重新标注任何图片。
4. 根据真实可读取的人工审核记录，写出“有数据支持的观察”和“尚未验证的假设”，不可将相关性直接写成因果结论。

输出一份新的中文报告，例如：`reports/v2_1_candidate_ui_review/coat_review_summary.md`，不要覆盖已有 `reports/v2_1_coat_pitbull_diagnostics/` 或 `reports/v2_1_diagnostics/`。

## 4. 技术实现要求

### 4.1 后端/推理层

- 新增独立、可单元测试的候选组判断与组内相对分数计算函数。
- 原始 top-1、原始概率向量、类别名称和现有 API 字段必须保持兼容。
- 建议在新字段中附加候选组信息（按项目现有命名风格），至少含：是否触发、候选组 canonical label、中文名、组内相对得分、触发理由/阈值版本。
- 不允许硬编码虚假的置信度。
- 候选阈值仅由 validation split 的模型输出确定，并在报告中记录：阈值、触发覆盖率、误触发案例、阈值选择依据。
- 不能因为类别不在当前模型标签空间中而抛错；V1.1 缺少 AmStaff 时必须自然退回原行为。

### 4.2 前端识别页

在 V2.1 能力被显式启用的测试/候选环境中：

- 主区域仍显示“模型首选”及模型原始 top-1。
- 触发候选组时，显示三类候选及“候选组内相对得分”。
- 加入简短说明，提示用户这只是相近品种候选，不代表模型已确认犬只的登记品种。
- 用户选择后，单独显示“你选择的品种”；“模型预测”不被替换。
- 未触发候选组时，原识别页面保持当前行为。
- 现有历史页、统计页和中文犬种名称显示不得回归。

### 4.3 功能开关

- 候选模式必须由显式配置/环境开关启用，默认关闭。
- 默认关闭时，正式 V1.1 行为和响应必须保持兼容。
- 不得直接改动 `config.py` 的正式模型默认路径，不得在本任务中把 V2.1 设为生产默认模型。

## 5. 测试要求

新增后端测试，至少覆盖：

1. top-1 为候选组成员且满足歧义阈值时，触发候选组；
2. 组内相对得分之和为 100%（允许浮点误差）；
3. 组内相对得分来自原始概率归一化，不修改原始概率向量；
4. 候选组总分太低或组内分差不满足触发条件时，不触发；
5. top-1 为其他类别时按定义正确处理；
6. 当前 V1.1 类别空间缺少 AmStaff 时不报错，保持旧行为；
7. 用户选择不会覆盖模型原始预测；
8. 原有识别、历史、统计、中文标签和训练扩展测试不回归。

前端如有测试框架，应补充主预测、候选展示、用户选择和默认关闭状态的测试；若没有现成框架，不得为此引入庞大依赖，需提供手工验证步骤。

执行：

```powershell
.venv\Scripts\python.exe -m pytest tests/ -q
```

并按项目当前实际命令运行前端检查/构建。报告精确列出通过数量和实际执行命令；不能声称运行过未执行的测试。
