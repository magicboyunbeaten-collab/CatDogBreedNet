# U6.3：默认启动行为核验与安全固化任务

> **目标**：确认日常启动配置下，V2.1（136 类）与两套相近犬种候选策略（四类 bully 组、`collie-pair`）的实际运行行为；随后对工作区进行轻量、安全的变更审计，为按范围固化代码做好准备。
>
> **本阶段不做**：不训练、不切换模型、不改阈值、不改标签或数据划分、不访问 test split、不修改正式数据库和上传目录、不清理工作区、不执行自动 Git 提交。

## 1. 阶段 A：确认默认启动配置（只读）

### A1. 静态检查

检查并记录以下内容，不修改文件：

- `config.py` 中默认 `weights_path`、`class_names_path`、`candidate_group_enabled` 的实际值及环境变量覆盖规则。
- `启动后端.bat`、`启动系统.bat` 中设置的 `CATDOG_*` 环境变量及模型路径检查逻辑。
- `main.py` 对模型路径、类别映射和候选开关的透传情况。
- 候选组分发函数如何根据原始 Top-1 选择 `four-breed-bully` 或 `collie-pair`，以及总开关关闭时如何处理。
- 检查 V1.1 37 类模型遇到这两组候选策略时的安全退回行为。

报告必须把以下概念分开记录：

1. **配置默认值**；
2. **启动脚本显式设置的值**；
3. **进程实际读取的有效值**；
4. **API 实际返回的行为**。

不得仅凭配置文件中的 `True/False` 就宣称功能已启用或关闭。

### A2. 只读运行证据

使用与日常启动入口相同的默认配置解析和环境变量规则，启动一个**隔离实例**进行检查。可在进程环境中重定向数据库、上传和临时文件路径，但不得修改正式配置文件或日常启动脚本。

核验：

- `/api/health` 显示 `num_classes: 136`，并能提供可验证的模型版本证据；不能只凭 `best_model.pth` 文件名判断版本。
- 有效候选总开关的真实值。
- 在默认配置下，四类 bully 策略是否会对预期验证样本触发。
- 在默认配置下，`collie-pair` 是否会对预期验证样本触发。
- 同样的图片在关闭候选总开关后，两类候选区域是否都不返回，而原始 Top-1、原始 Top-K 和原始分数保持一致。

**必须使用 `data/v2_processed/val` 中已有样本。严禁读取 `data/v2_processed/test`。**

推荐至少使用下列类别的 validation 图片（具体文件须从已有报告/CSV 中解析，不得凭空编造路径）：

- `collie-pair` 已知触发样本至少 1 张、已知不触发样本至少 1 张；
- 四类 bully 组已知触发样本至少 1 张、已知不触发样本至少 1 张；
- 一个不属于两组的对照类别至少 1 张。

若日常默认开关为关闭，应如实报告默认不触发的结果；**不要擅自将开关改为开启来声称默认功能已启用**。可另在隔离实例中做显式开启/关闭对照，但必须标明是覆盖配置的独立测试，而不是日常默认行为。

### A3. 候选触发与用户界面证据

确认以下语义：

- 原始模型 Top-1、Top-K 与原始分数不因候选提示被替换。
- 候选组内相对得分由完整概率按组内归一化得出；明确标注它不是整体置信度、校准后的真实概率，也不保证候选中一定包含正确品种。
- `collie-pair` 仅在当前阈值规则满足时提示，不以“黑白毛色”直接触发。
- 用户选择仅独立显示，不替换模型原始预测，不写数据库。
- 一张不触发候选的图片不应渲染相应候选区域。

注意：U6.2 当前验证集触发量极少（报告记录 3/2,079），不能将这项功能描述为提高了模型分类准确率，也不能推断它能解决模型高置信度的错误。
